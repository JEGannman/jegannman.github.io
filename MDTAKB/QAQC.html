Introduction

Data quality directly affects the fitness of data for use in applications, for supporting decisions, and the accuracy of any reports utilizing the data1. Data quality management involves the systematic and synergistic application of quality assurance (QA) and quality control (QC) protocols throughout the entire data lifecycle from creation to archival with the aim to maintain and improve overall data quality and usefulness.

  • Quality Assurance: Processes or methods to help prevent errors from being introduced into the data
  • Quality Control: Processes or tools to identify errors that are already in the data

The Maryland Transportation Authority (MDTA) is committed to ensuring the quality of all Authority datasets and will implement quality management protocols for all data in the Enterprise Geographic Information System (GIS).

This document represents a comprehensive QA/QC implementation guide and is relevant to anyone involved in editing or maintaining Enterprise GIS data. The primary objectives of this guide are as follows:

  • Identify the key elements of data quality and how they are addressed in this guide
  • Describe the Enterprise GIS QA/QC roles and associated responsibilities
  • Identify specific tools and resources to implement the QA/QC protocols
  • Outline all Enterprise GIS quality assurance protocols
  • Identify all Enterprise GIS quality control protocols
  • Guide users to implement specific quality control checks and workflows

Elements of Data Quality

According to the ISO 19157:2013 Geographic Information - Data Quality standards, there are six key elements of data quality as shown below:

Positional Accuracy { The accuracy of the position of features within a spatial reference system
Completeness { The presence and absense of features, their attributes and relationships
Temporal Quality { The quality of the temporal attributes and temporal relationships of features 
Thematic Accuracy { Classification correctness related to features and their attributes
Logical Consistency { Adherence to logical rules of data structure, attribution and relationships (documented in data product specifications)
Usability {  The data adhering to the user requirements for its intended use

Quality Assurance Protocols

Several quality assurance protocols are implemented within the MDTA Enterprise GIS system in order to ensure consistency and standardization across all GIS datasets and to reduce data entry errors. QA/QC reviewers shall evaluate all quality assurance protocols for each Enterprise GIS dataset to ensure they are correctly configured in accordance with all MDTA Enterprise GIS data and attribute standards and GIS best practice.

GIS data standards such as consistent attribute naming conventions, formatting rules and use of domains improves overall data quality and usefulness. MDTA's Office of Engineering Asset Management group maintains a GIS Standards Database with template feature classes for point, line, and polygon features as shown in Figure 4.

These templates include all minimum standard and recommended attributes and should be used as a starting point for creating new asset feature classes in the MDTA Enterprise GIS standard format described within this site

QA/QC reviewers shall ensure that all datasets included in the MDTA Enterprise GIS conform to the minimum standard data model and that any additional attribution conforms to attribute naming conventions and formatting rules. Additionally, when evaluating Enterprise GIS datasets, reviewers shall refer to the MDTA Enterprise GIS Data and Attribution Standards Guide and consider the following data model design questions:

  • ☐ Are GlobalIDs enabled?
  • ☐ Is Editor Tracking enabled?
  • ☐ If the dataset is related to other datasets, are the relationship fields and relationship classes configured correctly?
  • ☐ Are all minimum standard attributes included?
  • ☐ Are any additional, feature-specific attributes appropriately configured based on attribute formatting standards?

All MDTA Enterprise GIS feature classes shall utilize the projected and geographic coordinate systems listed below:

  • Projected Coordinate System: NAD 1983 HARN StatePlane Maryland FIPS 1900 (US Feet)
  • Geographic Coordinate System: NAD 1983 HARN

Dataset naming standards are employed in the MDTA Enterprise GIS to ensure thematic accuracy and logical consistency. QA/QC reviewers shall consider the following questions when reviewing new datasets added to the MDTA Enterprise GIS:

  • ☐ Does the dataset conform to the naming convention standards listed in the MDTA Enterprise GIS Data and Attribution Standards Guide?
  • ☐ Does the dataset utilize the standard coordinate systems?

Within the MDTA Enterprise GIS, subtypes are used to identify distinct groups of assets within a feature class in which multiple asset groups are combined. Specific subtype configurations are listed in Appendix A of the MDTA Enterprise GIS Data and Attribution Standards Guide.QA/QC reviewers shall refer to the Standards Guide when evaluating the following questions:

  • ☐ Does the dataset include a subtype attribute (ex. ASSET GROUP)?
    • ☐ If yes, are the subtype values configured consistently and accurately based on the context and type of features in the dataset?

Standard domains ensure data consistency and reduce user data entry errors. The MDTA Enterprise GIS Standards Database includes several pre-configured standard domains which are listed in the MDTA Enterprise GIS Data and Attribution Standards Guide.

Each MDTA Enterprise GIS database and individual dataset must be reviewed to ensure that all domains are correctly configured and mapped to applicable attributes. QA/QC reviewers shall consider the following questions:

  • ☐ Are the values for each domain correctly configured and consistent with Enterprise GIS standards?
  • ☐ Are domains correctly mapped to applicable attributes and subtypes?
  • ☐ Does an existing standard domain need to be updated with additional values to satisfy all attribution requirements?
  • ☐ Are there any additional, non-standard attributes that should use a domain?

Default values are another key method for reducing data entry errors and improving overall attribute completeness. Default values populate automatically when a new feature is added to a dataset. Because default values auto-populate, they should be used sparingly and are most appropriate for attributes for which specific information is not commonly available or for attributes that are typically the same across an entire dataset. The Appendix within this site lists all default values currently specified within the MDTA Enterprise GIS system.

When evaluating existing default values or reviewing newly added attributes, QA/QC reviewers shall consider the following questions:

  • ☐ Are default values configured according to the existing standards listed in the Appendix?
  • ☐ Are default values appropriate for a newly added attribute?
    • ☐ If yes, is the default value specified appropriate?

Attribute rules are user-defined rules that can be used to automatically populate attributes, restrict invalid edits during edit operations, and perform quality assurance checks on existing features. The following three types of attribute rules can be configured:

  • Immediate Calculation - automatically populate attributes based on editing patterns.
  • Constraint - control data entry by user-defined requirements.
  • Validation6 - highlight errors in existing data.

Immediate calculation attribute rules are primarily utilized within the MDTA Enterprise GIS to auto-calculate asset identifiers and auto-populate attributes based on specific values chosen for other attributes. For example, if the value chosen for the MOUNTING TYPE attribute is anything other than “Structure”, the STRUCTURE TYPE attribute will be automatically set to “Not Applicable”. Constraint rules are not currently used but they may be appropriate for future datasets or attributes. Validation rules are also not currently used in the MDTA Enterprise GIS since none of the data is branch versioned. However, the implementation of validation rules should be considered if branch versioning is adopted in the future. All attribute rules currently configured in the MDTA Enterprise GIS are listed in the Appendix.

When evaluating attribute rule configurations, QA/QC reviewers shall consider the following:

  • ☐ Are existing attribute rules configured according to the standards shown in the Appendix?
  • ☐ Are attribute rules appropriate for a newly added attribute?
    • ☐ If yes, what type of attribute rule is most appropriate?
  • ☐ Do configured attribute rules perform as expected (i.e. deliver expected results)?
6Validation rules are only usable if a dataset is configured as branch.
