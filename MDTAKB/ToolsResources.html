MDTA's Office of Engineering Asset Management (OEC AM) group maintains GIS reference map services related to the routes (facilities) that fall under MDTA responsibility, as shown in Figure 1.

The reference map services are published to the MDTA ArcGIS Portal and are shared at the Organization level so they are accessible by any user with access to the Portal. The MDTA_Reference_Layers_Combined map service is included by default in all MDTA asset viewer applications. Table 3 describes each reference map service and its intended usage.

Layer Name

Description

Usage

MDTA_Centerlines

These features are extracted from the Maryland Road Centerlines - Comprehensive feature service and include only the routes that fall under MDTA responsibility.

This layer can be used in place of the Maryland Road Centerlines - Comprehensive feature service to update road-related attributes for MDTA-specific routes.

MDTA_Mile_Markers

This layer contains all mile markers along MDTA routes (facilities).

Use this layer when populating the following standard attributes:

-          MILEMARKER

-          MILEMARKER_START

-          MILEMARKER_END

MDTA_Mile_Points_100th

These features are extracted from the MDOT SHA Mile Points (100th) feature service and include only the mile points for routes that fall under MDTA responsibility.

This layer can be used in place of the MDOT SHA Mile Points (100th) feature service to update road-related attributes for MDTA-specific routes.

MDTA_Exit_Numbers

These point features identify exit numbers along MDTA routes.

MDTA_Exit_Signs

These point features identify exit signs along MDTA routes

MDTA_ROW

These line features identify MDTA right of ways

MDTA_ICC_ROW

These line features identify MDTA right of ways along the Inter-County Connector

MDTA_Reference_Layers_Combined

This is a service that combines all of the other reference features listed above

Table 3: MDTA-Specific Reference Layer Details

The MDTA-maintained reference layers listed in Table 3 are updated periodically in line with new releases of the authoritative MDOT SHA iMap layers. Refer to the MDTA reference layer metadata for the date when a layer was last updated.

GIS data standards such as consistent attribute naming conventions, formatting rules and use of domains improves overall data quality and usefulness. MDTA’s Office of Engineering Asset Management group maintains a GIS Standards Database with template feature classes for point, line, and polygon features as shown in Figure 2.

These templates include all minimum standard and recommended attributes and should be used as a starting point for creating new asset feature classes in the MDTA Enterprise GIS standard format. Table 4 provides details about each feature class template

Standard domains ensure data consistency and reduce user data entry errors. Table 6 lists the MDTA Enterprise GIS standard domains that are templated in the GIS Standards Database.

Domain

Description

Standard_County

The county in which an asset is physically located. Includes all Maryland counties and non-Maryland counties in which MDTA assets are located.

Standard_CommunicationType

Describes the communication type of an asset.

Standard_Facility

The list of MDTA facilities (ex. BHT, FMT, FSK, etc.).

Standard_Location

The physical location of an asset to assist with locating it in the field (ex. Left Shoulder, Right Shoulder, Parking Lot, etc.).

Standard_LineInstallationType

Domain describing where a line is installed (ex. Bridge-attached, underground, etc.).

Standard_LineMode

Domain describing the mode of a line.

Standard_MountingType

A description of where an asset is physically mounted.

Standard_OffsetDirection

The offset direction of an asset from the edge of the pavement.

Standard_Organization

The organization responsible for owning and/or maintaining an asset.

Standard_Phase

The electrical phase of an electrical asset (ex. 1-Phase, 2-Phase, 3-Phase).

Standard_RoadDirection

The direction of a road or route (North, South, East, West).

Standard_ServiceStatus

The service status of an asset (ex. In-Service, Abandoned, Retired, etc.).

Standard_Spur

Identifies whether a route is a mainline, spur or ramp.

Standard_StructureType

The type of structure the asset is mounted on. This only applies if the Mounting_Type domain value "Structure" is picked.

Standard_YesNo

Valid Yes/No Values.
